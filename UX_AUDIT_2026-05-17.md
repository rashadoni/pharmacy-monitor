# UX / UI аудит leaddrive.cloud — 2026-05-17

Проход по 7 страницам: `/overview`, `/comparison`, `/site/pharmonline`,
`/site/aloe`, `/aloe-matcher`, `/alerts`, `/recipients`. Скриншоты собраны
браузерной автоматизацией. Severity: 🔴 critical (ломает функционал) /
🟡 important (мешает / путает) / 🟢 polish (чтобы выглядело дорого).

## 🔴 Critical (5 проблем)

### 1. «Сегодняшние действия» бесконечный «Загрузка…» на 3 страницах
- На `/overview`, `/site/pharmonline`, `/site/aloe` секция ROI рекомендаций
  висит без таймаута и без ошибки
- API `/dash/roi/actions` либо падает silently либо считается дольше 30+ сек
- **Fix**: добавить timeout 10с в React Query + показать «Не удалось загрузить»
  с retry-кнопкой; параллельно профайл `roi.compute_actions()` на проде

### 2. «Топ брендов» пустой на `/site/pharmonline` и `/site/aloe`
- KPI говорит «6441 брендов», а блок «Топ брендов на pharmonline» — «Нет данных»
- Root cause: `analytics.brand_share()` фильтрует `WHERE PriceSnapshot.run_id == last_ok_run`. После diff-only persist + неудачного aloe-скрейпа сегодня (`run_69 products_scraped: 0`) запрос возвращает 0 строк.
- **Fix**: brand_share → `latest_snapshots_per_product` вместо `run_id` (та же история что в [src/analyzer.py refactor 2026-05-09](src/storage.py))

### 3. Zombie-runs занимают таблицу `runs` (статус «running» 21h / 69h)
- На `/overview` видно `run_id=70` running 21ч 20м и `run_id=67` running 69ч 20м
- Это сломанные процессы которые не закрылись, шумят в графике и smoke-test'е
- **Fix**: добавить cleanup-cron: `UPDATE runs SET status='failed', error_message='zombie cleanup' WHERE status='running' AND started_at < NOW() - INTERVAL '6 hours'`

### 4. Aloe скрейпер сломан сегодня (`run_69` = 0 продуктов)
- Каждое утро 03:00 UTC падал — за вчера и сегодня 0 продуктов с aloe.az
- Это **breaking** для бизнеса: aloe данные стареют, alerts не обновляются
- Скорее всего Cloudflare поставил challenge / aloe изменил селекторы
- **Fix**: запустить scrape вручную + посмотреть логи `journalctl -u pharmacy-monitor-scrape@aloe`

### 5. Категории отображаются как technical slugs
- `/site/aloe` показывает: `dermanlar`, `usaq-dunyasi`, `bad`, `uşaq-qidası`, `product_field=bestseller`
- `/site/pharmonline` показывает: `ushaqlar-uchun-vasiteler`, `gigiyenik-vasiteler`, ...
- В БД есть `Category.label_ru` поле, но фронт его не использует
- Особенно плохо: `product_field=bestseller` — leaked query-string как «категория»
- **Fix**: добавить JOIN на `categories.label_ru` в `/dash/products/facets` или сделать lookup-table во фронте

## 🟡 Important (10 проблем)

### 6. KPI лейблы в разных языках на разных страницах
- `/overview`: «CROSS-SITE MATCHES», «COVERAGE», «PRODUCTS», «AI-NORMALIZED» — **английский UPPER**
- `/site/[name]`: «ВСЕГО ПРОДУКТОВ», «БРЕНДОВ», «СО СКИДКОЙ» — **русский**
- **Fix**: вынести все label в i18n keys, унифицировать русскую версию (либо везде английский если планируется international)

### 7. `nav.recipients` показывается как raw key в сайдбаре
- После моего deploy ru.json обновился, но frontend bundle закэшировался
- Пользователю надо Cmd+Shift+R + ещё может быть проблема в build-time bundling
- **Fix**: проверить что `frontend/messages/ru.json` попал в build (`grep -r recipients frontend/.next`); если нет — pnpm build не подхватил изменение

### 8. «Бренд» column на `/comparison` бесполезный
- Колонка «Бренд» дублирует первое слово из «Название»: «Novokain 0.5% 2 ml N10» → бренд «Novokain»
- 90% строк имеют этот pattern → колонка ничего не добавляет
- **Fix**: либо извлекать бренд из normalized_attrs.brand_canonical (если есть), либо убрать колонку

### 9. Большинство spread = 0.0% на `/comparison` — visual noise
- pharmonline и aptekonline часто берут данные из одного дистрибутора, цены идентичные
- Стол на 90% забит «0.0%» строками, важные различия теряются
- **Fix**: добавить toggle «Только с отличающимися ценами» (spread > 0) по умолчанию ON

### 10. aloe-колонка на `/comparison` мостит пустоты «—»
- 90%+ ячеек aloe = «—». Колонка занимает место без пользы.
- **Fix**: hover-tooltip «aloe: нет данных» вместо отдельной колонки. Или показывать aloe только когда есть.

### 11. Auto-search в `/aloe-matcher` слишком специфический
- При открытии каждой строки автоматически подставляется `${brand} ${name} ${dosage}`
- Часто это дубликат («Fluvir-Os Fluvir-OS suspenziya 6 mq/ml 60 ml») → 0 результатов
- Пользователь должен сократить вручную
- **Fix**: автоподставлять только `canonical_brand` или первые 2 слова имени

### 12. Нет bulk-actions на `/aloe-matcher` (2987 кластеров вручную)
- «Пропустить» по одной кнопке × 2987 = неделя работы
- Нет «Пропустить всю категорию», «Пропустить дешёвые (<5 AZN)»
- **Fix**: фильтр-suggest «Топ-50 дороже 30 AZN» + bulk skip

### 13. Mobile view ломается на `/comparison`
- Стол с 6+ колонками не помещается в 375px
- Скорее всего горизонтальный скролл, неудобно с телефона
- **Fix**: card-layout на md+ breakpoint (как на /site/[name])

### 14. Нет timestamp consistency
- `/alerts`: «17 мая, 03:30» — короткий формат
- `/overview` runs: «2026-05-17 03:02» — ISO
- `/site/[name]`: «16 мая, 03:01 — run #69» — слегка другой формат
- **Fix**: одна функция `formatTime` для всех, относительные («5 мин назад» / «вчера») для последних 24ч

### 15. 12 пунктов в сайдбаре — слишком много
- Comparison, Обзор, pharmonline, aptekonline, aloe.az, Aloe матчер, Аналитика, Алерты, Watchlist, Категории, Получатели, Настройки
- Большой sidebar давит, мобильный bottom-nav показывает только первые 5 (нелогичный выбор)
- **Fix**: group-headers («Сайты», «Действия», «Настройки»), либо collapse-секции; iconography чтобы текст не нужен

## 🟢 Polish (8 проблем)

## Доступность (3 проблемы)

### A1. Color contrast `text-muted-foreground` под вопросом
- Серый текст на белом — может не пройти WCAG AA на каких-то фонах
- **Fix**: запустить axe-core / Lighthouse на каждой странице, поднять muted-foreground contrast

### A2. Tooltip-only hints не работают на touch
- `title="..."` на mobile невидим
- **Fix**: для критичных хинтов сделать inline microcopy

### A3. Form errors generic
- Pydantic 422 показывает «String should have at least 3 characters» — английский, технический
- **Fix**: переводить error messages в frontend, показывать поле-инлайн
