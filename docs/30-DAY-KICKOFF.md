# 30-day kickoff plan для pharmonline пилота

План первых 30 дней работы pharmacy-monitor с pharmonline.az. Цель пилота —
доказать что система даёт измеримую ценность (`+X ₼ маржи` или
`-Y ₼ потенциальных потерь`) и обоснованно остаться на постоянку.

---

## Метрики успеха пилота

К концу 30-го дня:

| Метрика | Цель | Как измеряем |
|---|---|---|
| **Uptime** скрейперов | ≥95% | `pharmacy-monitor alert recent --days 30` → 0 critical site_drop |
| **Сматченных SKU** на 3 сайтах | ≥50 | Дашборд → Аналитика → "Сматченных кластеров" |
| **Manual %** (доверие к системе) | ≥30% | Дашборд → Аналитика → "Manual %" |
| **Открытий дашборда** клиентом | ≥3/неделя | Логи nginx (можно дополнительно настроить) |
| **Алертов сработало** | ≥5 | `pharmacy-monitor alert recent --days 30` |
| **Действий клиента** в ответ на алерт | ≥2 (изменили цену) | Опрос на 4-неделе |

Если 4 из 6 метрик достигнуты — пилот успешен → переход на постоянку.

---

## Неделя 1 — Bring-up

**Цель:** клиент получает первый отчёт. Скрейпинг работает на 3 сайтах.

| День | Кто | Что |
|---|---|---|
| Mon | Подрядчик | Provision VPS + nginx + SMTP + первый прогон |
| Mon | Клиент | Ответить на [ONBOARDING-CHECKLIST.md](ONBOARDING-CHECKLIST.md) |
| Tue | Подрядчик | Добавить 3 URL категорий клиента → запустить prod-прогон |
| Tue | Клиент | Получить первый email-отчёт. Открыть дашборд (логин: см. RUNBOOK) |
| Wed | Клиент | Прокликать ✓/✗/🔍 на 10-20 матчах в Сравнении (~30 мин) |
| Thu | Подрядчик | Health-check на серьёзности (нет site_drop?). Корректировки в скрейперах если нужно |
| Fri | Совместно | 15-минутный созвон retro: что работает, что нет |

**Acceptance Week 1:**
- Email-отчёт доходит каждое утро
- Дашборд открывается с auth
- Хотя бы 5 матчей подтверждены клиентом

---

## Неделя 2 — Coverage + Alerts

**Цель:** покрыть значимый ассортимент + включить real-time алерты.

| День | Кто | Что |
|---|---|---|
| Mon | Клиент | Передать список топ-50 SKU для watchlist (по приоритету маржи или объёма) |
| Mon | Подрядчик | Импортировать watchlist (если есть `client.csv`) или добавить через дашборд |
| Tue | Подрядчик | Настроить 3-5 правил алертов (см. шаблон ниже) |
| Tue | Клиент | Запустить Telegram-бота (`/start`) → передать chat_id |
| Wed-Thu | Клиент | По мере накопления данных — продолжить ✓/✗ на новых матчах |
| Fri | Совместно | Retro: что в дашборде используется, что нет |

**Шаблон правил для Mon Tue:**
```
1. undercut_threshold      — порог 5%, channels: email + telegram
2. price_drop_pct          — порог 15%, channels: email
3. new_product             — без порога, channels: email
4. promo_started           — channels: telegram (быстро реагировать)
5. price_raise_opportunity — порог 10%, channels: email еженедельный
```

**Acceptance Week 2:**
- В Сравнении ≥30 сматченных кластеров
- Хотя бы 1 алерт сработал и доехал по email/Telegram
- Manual % > 15%

---

## Неделя 3 — Validate ROI

**Цель:** показать **числовой результат** работы системы.

| День | Кто | Что |
|---|---|---|
| Mon | Подрядчик | Открыть дашборд → Обзор → "Сегодняшние действия". Записать топ-5 действий с impact в ₼ |
| Tue | Клиент | По 2-3 действиям из топа — реально изменить цену в pharmonline |
| Wed-Fri | Клиент | Наблюдать: после изменения цены — упали ли продажи (если дани были вверх) или выросла маржа |
| Fri | Совместно | Тест-кейс: один SKU где клиент поднял цену по совету системы → измерить эффект |

**Acceptance Week 3:**
- Минимум 1 SKU где клиент изменил цену по рекомендации
- Видим эффект (даже если "цена осталась стабильной у конкурентов" — это уже ROI)

---

## Неделя 4 — Scale + Decision

**Цель:** расширить покрытие до полного объёма + принять go/no-go решение.

| День | Кто | Что |
|---|---|---|
| Mon-Wed | Совместно | Расширить watchlist до 100-300 SKU. Добавить остальные релевантные категории |
| Thu | Подрядчик | Аналитика: какие сайты дают больше всего полезных алертов? Где скрейперы стабильнее? |
| Fri | Совместно | **Решение по продолжению:** |
|  |  | 🟢 Доволен → переход на платный месячный контракт |
|  |  | 🟡 Частично — нужно доделать → дотюнить (1-2 недели) |
|  |  | 🔴 Не подходит → честный рапорт + рекомендации |

**Acceptance Week 4:**
- Все 6 метрик из таблицы вверху измерены
- Решение принято и зафиксировано

---

## Что меняем в Pharmacy Monitor по результатам пилота

После недели 4 — обсуждение бэклога:

### Если Manual % < 30%
- Усилить fuzzy matcher (нужны новые правила нормализации?)
- Migrate на более точный matching algorithm
- Возможно — добавить ML embeddings (sentence-transformers)

### Если site_drop > 1 раз/месяц
- Усилить scraper hardening
- Добавить fallback selectors
- Регулярные snapshot-tests

### Если у клиента вопросы "а что с маржой?"
- Запросить supplier prices (CSV)
- Включить Inventory модуль (тогда ROI уже не условный)

### Если клиент хочет 2-й контракт
- Активировать multi-tenant query scope (сейчас skeleton)
- Per-client deploy automation

## Риски пилота и митигация

| Риск | Митигация |
|---|---|
| Клиент не открывает дашборд | Замена на email+Telegram only |
| Слишком много ложных матчей → клиент устал корректировать | Снизить fuzzy threshold, увеличить precision |
| Сайт сменил вёрстку в первую неделю | Snapshot-tests + быстрый turnaround на фикс |
| Email уходит в спам | Перенастроить SPF/DKIM, или сменить SMTP-провайдера |
| Telegram-бот падает | systemd auto-restart + alert |

## Шаблон еженедельного review (15 минут)

```
1. Что произошло на этой неделе? (alerts / actions taken)
2. Что не работает или раздражает?
3. Какие SKU / категории добавить / убрать?
4. На что клиент потратил время? Что получил взамен?
5. Что нужно от подрядчика на следующей неделе?
```

Записать в shared doc → конец каждой пятницы.
