# Как изменения доезжают до пользователей

Тот же порядок, что и в `leaddrive-v2` (полный текст с историей — там же,
`docs/DELIVERY-ARCHITECTURE.md`). Действует одинаково для всех сессий: Claude,
Codex, любых будущих.

Владелец работает один и не читает диффы. От него требуется ровно две вещи: один
раз добавить ключ и перед релизом ответить «давай» на короткий список.

## Зачем это появилось

6 сентября 2026 года в `main` соседнего репозитория за день влилось восемь PR под
именем владельца. Четыре из них он не открывал — включая фичу на главной, которую
никто не заказывал. Защиты у ветки не было никакой. Зелёные тесты означают «то, о
чём подумал автор, работает»; они ничего не говорят о том, о чём автор забыл, и
тем более о том, нужна ли эта работа вообще.

## Слой 1. В `main` только через pull request

Прямой пуш запрещён правилом репозитория. Обязательная проверка ровно одна —
`agent-review`, потому что она запускается на каждом PR, включая PR без кода.
Тяжёлые проверки остаются с фильтрами по путям и обязательными не делаются: иначе
PR с одной правкой в тексте висел бы вечно, ожидая проверку, которая для него не
стартует.

Настраивается не руками, а скриптом `scripts/ci/configure-main-protection.sh`.

Одобрения ревьюера не требуются: владелец работает один, и правило, которое
некому выполнить, останавливает доставку вместо того, чтобы её защищать.
`enforce_admins` выключен осознанно — это аварийный выход, и каждый его случай
стоит называть вслух.

## Слой 2. PR разбирает агент, который его не писал

`.github/workflows/agent-review.yml` даёт диф отдельному агенту. У него нет
заинтересованности в этом коде: он не выбирал решение и не устал его защищать. Он
сверяет изменение с тем, что задача требовала, и ищет дефекты.

Найдено настоящее — проверка красная, смержить нельзя. Замечания вида «здесь можно
было короче» в блокирующий вывод не попадают, иначе гейт превращается в шум,
который учатся обходить. Блокирующее замечание проходит второй взгляд, прежде чем
уронить проверку.

Если `ANTHROPIC_API_KEY` нет или API сбоит, проверка проходит, но в PR прямым
текстом пишется, что изменение **никто не разобрал**. Мерж после такого — чьё-то
решение, а не то, что проскользнуло само.

## Слой 3. Прод

Всё, что уже построено в этом репозитории для выкладки: сборка, проверка здоровья,
откат. Слой 2 его не заменяет и не ослабляет.

## Слой 4. Слово владельца

Единственное, чего машина не может: «я такого не заказывал». Перед мержем того,
что увидит пользователь, показать короткий список — по одной строке на изменение,
человеческим языком, без имён файлов — и дождаться «давай».

Список нужен только для видимого. Правки тестов, документации и внутренних
скриптов в него не попадают.

## Что обязан делать любой агент

1. Не пушить в `main`. Только PR.
2. Не мержить красное и не ослаблять проверку, чтобы пройти.
3. Не мержить, пока `agent-review` не зелёный.
4. Перед мержем видимого — список из слоя 4 и «давай».
5. Своё же ревью не считается.
