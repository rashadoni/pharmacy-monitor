Что нужно сделать на стороне клиента в первую неделю, чтобы система начала
давать осмысленные данные.

- [ ] **Доступ к pharmonline.az** не требуется (только публичная часть)

## День 1 — выбрать что мониторить

Два варианта (можно совмещать):

### А. Категории (массовый мониторинг)
Выбрать 3-5 категорий-приоритетов. По каждой нужны 3 URL'а:

| Категория | pharmonline | aptekonline | aloe |
|---|---|---|---|
| Детское питание | https://pharmonline.az/products?category=ushaq-qidasi | https://aptekonline.az/products/252 | https://aloe.az/catalog/filters/?category_slug=uşaq-qidası |
| _________ | _________ | _________ | _________ |
| _________ | _________ | _________ | _________ |

**Как найти URL:**
1. Открой каждый сайт в браузере
2. Найди категорию через каталог / поиск
3. Скопируй URL из адресной строки
4. Передай подрядчику для добавления через дашборд

### Б. Watchlist (точечный мониторинг конкретных SKU)
Список из 30-100 SKU где важна точная цена-конкуренция. На каждый — 3 URL'а:

```csv
canonical_name,brand,dosage,pack_size,pharmonline_url,aptekonline_url,aloe_url
Friso Gold 1 800g,Friso,,800g,https://pharmonline.az/...,https://aptekonline.az/...,https://aloe.az/...
Aspirin Cardio 100mg N30,Bayer,100mg,N30,...,...,...
```

Сохрани как `watchlist.csv` → подрядчик импортирует через
`pharmacy-monitor watchlist import`.

## День 2 — получить первый отчёт

После того как подрядчик настроит:
- [ ] Утром в 06:00 AZT (UTC+4) → email в inbox с темой "Pharmacy Monitor — DD.MM.YYYY"
- [ ] HTML-письмо + Excel вложение
- [ ] Если нет → проверить spam, написать подрядчику

## Дни 3-7 — корректировка матчей (КРИТИЧНО)

Открой дашборд → 🔍 **Сравнение цен** → пройдись по карточкам:

- ✓ **Подтвердить** — если матч правильный (один и тот же товар на 3 сайтах)
- ✗ **Не один товар** — если матч ложный (разные товары случайно склеены)
- 🔍 **Заменить** — если есть правильный кандидат, но не подтянулся

Полная инструкция: [MATCHING-GUIDE.md](MATCHING-GUIDE.md)

**Норма для первой недели:** 30-60 минут в день.
**Норма потом:** 5-10 минут в неделю на новые SKU.

## День 7 — настроить алерты

Дашборд → 🔔 **Алерты** → ➕ Добавить правило:

| Тип | Что детектирует | Когда полезно |
|---|---|---|
| `undercut_threshold` (5%) | Конкурент опустил цену ниже клиента ≥5% | Главная защита маржи |
| `price_drop_pct` (10%) | Резкое падение цены любого сайта | Кто-то сделал акцию |
| `price_change_pct` (5%) | Любое заметное изменение цены (вверх или вниз) | Быстро узнать об изменении цены конкурента |
| `new_product` | Новый SKU на конкуренте | Расширение ассортимента |
| `promo_started` | Новая промо-кампания у конкурента | Ответный ход |
| `price_raise_opportunity` (7%) | Клиент сильно дешевле — можно поднять | Рост маржи |

**Каналы:** email + Telegram (если настроен бот).

## День 14 — review с подрядчиком

Раз в 2 недели созвон 30 минут:
- [ ] Что делает клиент с отчётами?
- [ ] Какие алерты пришли — на что реагировал?
- [ ] Что не работает / неудобно?
- [ ] Расширить watchlist? Добавить категории?
- [ ] Изменить пороги алертов?

## Что клиент НЕ делает (это работа подрядчика)

- Деплой и обновления кода
- Починка скрейперов когда сайты меняют вёрстку
- Бэкапы / восстановление БД
- Email-рассылку
- Настройку SMTP / Telegram токенов

## Контакты для эскалации

- **Не работает дашборд** → подрядчик
- **Сломан скрейпер** (health-check email пришёл) → подрядчик
- **Email не доходит** → подрядчик + проверь spam
- **Цена в отчёте не совпадает с сайтом** → подрядчик (возможно баг парсинга)

## Финальное

После 30 дней пилота — обсуждение продолжения:
- Объём работы (сколько SKU / категорий)
- Цена обслуживания
- Доп. фичи (Telegram, API, Inventory модуль)
