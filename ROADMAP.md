# Pharmacy Monitor — Roadmap

> **Горизонт:** 12 месяцев (Apr 2026 — Apr 2027)
> **Ресурс:** 1 человек, full-time (~140 ч/мес продуктивной работы)
> **Цель:** Сдать pharmonline.az → решить пивотить ли в SaaS → построить продукт
> **Приоритет H1:** Расширение функционала (Telegram, алерты, депт)

---

## Видение

Pharmacy Monitor превращает "ежедневный обзвон конкурентов" в **автоматический системный мониторинг с real-time алертами**.
Конечная цель — стать стандартом ценовой разведки в фарм-рознице Азербайджана / Кавказа, начиная с одного якорного клиента (pharmonline.az).

## Принципы

1. **Sell results, not features.** Каждая фича должна давать клиенту конкретное решение (поднимай цену → +X ₼/мес).
2. **Один клиент учит лучше десяти.** До конца Q1 — никаких новых клиентов. Pharmonline даст 80% feedback'а.
3. **Solo-friendly.** Никаких внешних сервисов которые нельзя самому отлаживать в 23:00.
4. **Boring tech.** SQLite → Postgres только когда нужно. Стек уже выбран (Python + Playwright + Streamlit) — не переписывать.
5. **Kill schedule.** Каждый квартал — decision gate. Не идёт — пивот без сожалений.

## Q1 — FOUNDATION (Apr 28 — Jul 28)

**Тема:** Pharmonline в продакшен. Основные фичи. Реальные данные → реальные решения.

**Гипотеза квартала:** Если построить надёжный мониторинг + Telegram-алерты + ручную коррекцию матчей — pharmonline.az будет ежедневно использовать продукт и платить за него.

### Месяц 1 (Apr 28 — May 26): Production hardening

| Неделя | Deliverable | Acceptance |
|---|---|---|
| W1 | **MatchRejection + manual UI** (Phase 2 из предыдущего плана) | Клиент может ✓ подтвердить или ✗ развязать матч прямо в Сравнении |
| W2 | **Robust scrapers** — пагинация, retry, alerts при сломе | На 100+ товарах baby food отдают полный листинг без ручного вмешательства |
| W3 | **VPS deploy** + cron + nginx + SSL + basic auth | Pharmonline получает первый автоматический ежедневный email |
| W4 | **Demo-mode** + ROI-калькулятор на главной | На пустой БД дашборд показывает sample-данные с переключателем "Demo / Real" |

**Critical:** к концу месяца pharmonline получает ежедневный отчёт без моего вмешательства.

### Месяц 2 (May 26 — Jun 23): Real-time alerts

| Неделя | Deliverable | Acceptance |
|---|---|---|
| W5 | **Telegram bot** — `/start`, `/alerts on/off`, `/today` | Клиент получает мгновенное уведомление при любом изменении цены конкурента |
| W6 | **Alert rules engine** — пороги, watchlist-фильтр, частота | UI для настройки: "только undercuts >5% по топ-50 SKU, не чаще 1 раза в час" |
| W7 | **Hourly micro-scrape** для топ-100 watchlist товаров | Реалтайм-окно мониторинга. Раздельный cron от ежедневного полного |
| W8 | **Multi-channel notifications** — email-instant, Telegram, web push | Клиент выбирает где он получает алерты |

**Differentiator:** конкуренты делают ежедневный отчёт. Мы — мгновенный triggered alert. Это main selling point.

### Месяц 3 (Jun 23 — Jul 28): Depth & polish

| Неделя | Deliverable | Acceptance |
|---|---|---|
| W9 | **Брэнд-аналитика** — share по брендам, кто эксклюзивный дистрибьютор | Отдельный отчёт раз в неделю: "Bayer представлен у 3 сайтов; Sanofi только у 2" |
| W10 | **Промо-tracker** — кампании, длительность, глубина | Heatmap: когда конкуренты делают акции по сезонам |
| W11 | **Mobile-responsive дашборд** + PDF-экспорт отчётов | Клиент открывает с телефона и читает; для совещания — PDF в одну кнопку |
| W12 | **30-дневный feedback loop** с pharmonline | NPS-опрос, разбор реальных кейсов, фиксы по итогам |

### 🚦 Q1 Decision Gate (конец Jul)

**Метрики:**
- ✅ Pharmonline использует ежедневно (открывает дашборд / читает email ≥5 дней/неделя)
- ✅ Сматченных кросс-сайтовых товаров ≥ 200
- ✅ NPS ≥ 7
- ✅ Pharmonline платит / готов рекомендовать
- ✅ Uptime скрейпинга ≥ 95%

**Решение:**
- 🟢 **5/5 метрик OK** → Q2 = SaaS-направление (Branch A)
- 🟡 **3-4/5 OK** → Q2 = углубление в pharmonline (Branch B "agency-mode")
- 🔴 **<3 OK** → Pivot или закрытие. Не страшно, ценный урок.

## Q2 — DECISION-FORK (Jul 28 — Oct 27)

### 🅐 Branch A: SaaS-readiness (если Q1 успешен)

**Тема:** превратить pharmonline-инсталляцию в продукт для других аптек.

| Месяц | Deliverable |
|---|---|
| **Mes 4** | Multi-tenant DB (`tenant_id` everywhere), auth (magic link), billing (Stripe / Paddle / local provider) |
| **Mes 5** | Self-service onboarding — sign up → подключить домен → автоматический скрейпинг конкурентов из коробки. Brand identity, landing page |
| **Mes 6** | Готовность к 5 параллельным клиентам. Health-monitoring всех инсталляций. Knowledge base + 5 видео-туториалов |

**Метрики Q2A:** время от signup до первого отчёта ≤ 30 минут. Платный pilot-клиент №2 подключён.

### 🅑 Branch B: Deep agency-mode (если Q1 средний)

**Тема:** pharmonline — единственный клиент, делаем его максимально успешным.

| Месяц | Deliverable |
|---|---|
| **Mes 4** | Inventory module — связка с складом клиента (CSV-импорт остатков → "опусти цену пока есть запас") |
| **Mes 5** | Supplier integration — закупочные цены → margin-аналитика на каждый товар |
| **Mes 6** | Custom dashboards под отделы (закупки / маркетинг / руководство) |

**Метрики Q2B:** pharmonline платит больше за расширения. Контракт на 12 мес.

## Q4 — SCALE OR PIVOT (Jan 26 — Apr 28)

| Сценарий | Что делать |
|---|---|
| **Scale**: 10+ клиентов, ARR растёт | Найм первого помощника (customer success или дев). Inbound-маркетинг (SEO, content). |
| **Plateau**: 5 клиентов стабильно но не растёт | Углубить продукт (Phase 3-фичи), повысить чек, удерживать. |
| **Pivot**: <3 клиента или churn высокий | Анализ урока. Возможные пивоты: 1) e-commerce price-monitor (выйти за фарму), 2) inventory-optimization SaaS, 3) сторонний дистрибьюторский продукт. |

**Q4 deliverables (для сценария Scale):**
- API для интеграции с ERP клиентов
- Predictive pricing — ML-модель оптимальной цены при заданных margin/volume целях
- Конкурентный анализ за пределами 3 сайтов (региональная экспансия)

## Риски и митигация

| Риск | Вероятность | Удар | Митигация |
|---|---|---|---|
| Pharmonline отказывается продолжать | средняя | критический в Q1 | Иметь 2-3 backup-кандидата на тёплых контактах к концу Q1 |
| Скрейперы ломаются от смены вёрстки | высокая | средний | Автотесты на снапшотах + alert при padении товаров >50% от baseline |
| Юр. иск от конкурентов за скрейпинг | низкая | высокий | Соблюдение robots.txt, разумный rate-limit, не публиковать чужие данные публично, юр. консультация в начале Q2 |
| Solo burnout | средняя | критический | 5-дневная неделя, 1 неделя отпуска в квартал, no on-call в первые 6 мес |
| Конкурент быстрее выходит | низкая (текущий рынок) | средний | Фокус на скорости итераций, не на perfection |
| Платежи в Азербайджане | средняя | средний | На старте — банковский счёт + Wire. Потом — Paddle/Stripe через юр.лицо |
| Технический долг растёт | высокая | средний | 1 неделя в квартал — refactor only. Метрика: тесты coverage ≥ 60% к концу Q1 |

## Anti-goals (что НЕ делаем)

- ❌ Скрейпинг сайтов вне Азербайджана до Q4 (фокус)
- ❌ Mobile-app до Q3 (web-responsive хватает)
- ❌ Свой ML/AI до Q4 (rule-based system покрывает 90%)
- ❌ White-label / on-premise до Q3 (multi-tenant SaaS — лучшая модель)
- ❌ Бесплатный план — только 14-дневный trial
- ❌ Одновременный фокус на 2+ продуктовых направлениях

## Принципы execution

1. **Каждый понедельник** — план на неделю в этот файл (раздел "Этой недели"). В пятницу — retro.
2. **Каждый месяц** — пересмотр Roadmap. Если Q-метрики на месяц ниже плана — корректирующие меры на следующий месяц.
3. **Каждый квартал** — Decision Gate. Жёсткое решение: continue / branch / pivot.
4. **Не более 3 крупных feature'ов в работе одновременно.** Иначе ничего не доделывается.
5. **Доставлять каждые 2 недели** что-то юзабельное в pharmonline. Невидимый прогресс убивает мотивацию.
